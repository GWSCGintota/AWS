01 — Foundations

What is Amazon S3?

Amazon Simple Storage Service (Amazon S3) is AWS object storage. It stores data as objects in buckets and is designed for high durability, massive scale, fine-grained access control, and integration with the wider AWS ecosystem.

◫

Store any file type

Images, videos, documents, backups, logs, datasets, application assets, and archives.

↗

Scale automatically

You do not provision disks or manually increase capacity as data grows.

⌁

Access through APIs

Use the AWS Console, CLI, SDKs, REST API, applications, and supported AWS services.

⚿

Control access

Use IAM policies, bucket policies, access points, Block Public Access, and encryption.

Common use cases

Backup and disaster recovery

Store backups, database exports, snapshots, and recovery data with versioning and lifecycle policies.

Data lakes and analytics

Centralise structured and unstructured data for services such as Athena, Glue, EMR, Redshift, and SageMaker.

Application assets

Store user uploads, media, software packages, logs, reports, and static files.

Static websites

Host HTML, CSS, JavaScript, images, and downloadable files without running a web server.

Archiving and compliance

Use Glacier classes, Object Lock, retention policies, and audit logs for long-term retention.

Content distribution origin

Use a private S3 bucket behind Amazon CloudFront for global delivery, HTTPS, and caching.

S3 is not a traditional file system. It is object storage. Applications normally address an entire object by its key rather than modifying individual disk blocks.

02 — Vocabulary

Core S3 concepts

Bucket
A top-level container for objects. A bucket is created in an AWS Region and has configuration for access, encryption, versioning, lifecycle rules, events, and more.
Object
The stored data plus metadata. An object may be an image, PDF, CSV file, backup, video, or any other data item.
Object key
The full identifier of an object inside a bucket, such as images/products/item-01.jpg.
Prefix
A shared beginning of object keys used to organise and filter objects. S3 consoles display prefixes like folders, but S3 has a flat object namespace.
Metadata
Information associated with an object, such as content type, cache control, encryption information, tags, and custom user-defined metadata.
Region
The AWS geographic area where the bucket is created. Choose a Region based on latency, data residency, service availability, and cost.
Storage class
The cost and access profile used for an object, ranging from frequent access to deep archive and ultra-low-latency single-zone storage.
Version ID
A unique identifier assigned to an object version when S3 Versioning is enabled.
ETag
An object response identifier often used for caching or change detection. It should not always be treated as a simple MD5 checksum, especially for multipart or encrypted uploads.

Example object address

s3://my-learning-bucket/website/assets/logo.png
│        │                  └─ Object key
│        └─ Bucket name
└─ S3 URI scheme
Bucket naming matters. General-purpose bucket names are globally unique within the relevant AWS partition. Names and Regions cannot be changed after creation.

03 — Architecture

How Amazon S3 works

A client authenticates to AWS, sends a request to an S3 endpoint, and performs an allowed operation on a bucket or object.

💻 Client or application Console, CLI, SDK, browser, service
→
🔐 Authentication and authorisation IAM role, identity policy, bucket policy
→
🪣 S3 bucket and object Region, key, metadata, storage class

Typical request sequence

1. Resolve endpoint→ 2. Sign request→ 3. Evaluate permissions→ 4. Read or write object→ 5. Record logs/metrics

Data plane operations

Operations that work with objects.

GetObject PutObject DeleteObject CopyObject ListObjectsV2

Control plane operations

Operations that configure buckets and their behaviour.

CreateBucket PutBucketPolicy PutBucketVersioning PutLifecycleConfiguration

Important capacity facts

  • A bucket can hold a very large number of objects; AWS documents no fixed maximum bucket size or object count.
  • A single PUT operation supports objects up to 5 GB.
  • The S3 console supports uploads up to 160 GB.
  • Large objects should use multipart upload. Current AWS documentation describes a maximum object size of approximately 50 TB.
  • A bucket cannot contain another bucket. Folder-like organisation is created using prefixes in object keys.
Large-object guidance can change. Always confirm multipart limits in the current AWS documentation before designing a workload around maximum object size.

04 — Storage design

S3 storage classes

Select a storage class based on access frequency, retrieval speed, resilience requirements, minimum storage duration, and retrieval fees.

Storage class Best for Access pattern Retrieval profile Key consideration
S3 Standard
Frequent access		 Web assets, active datasets, applications, frequently read content Frequent or unpredictable Millisecond access General default for active workloads
S3 Intelligent-Tiering
Automatic		 Data with unknown, changing, or unpredictable access patterns Automatically moves data among access tiers Low-latency for online tiers; optional archive tiers vary Monitoring and automation charges may apply per object
S3 Standard-IA
Infrequent		 Backups and less frequently accessed data needing multi-AZ resilience Infrequent, but must remain quickly available Millisecond access Retrieval charges and minimum-duration considerations
S3 One Zone-IA
Single AZ		 Re-creatable secondary copies and non-critical infrequent data Infrequent Millisecond access Stored in one Availability Zone; not suitable for every resilience requirement
S3 Glacier Instant Retrieval
Rare access		 Archives that are rarely accessed but must be retrieved immediately Rare Millisecond access Retrieval charges and longer minimum storage duration
S3 Glacier Flexible Retrieval
Archive		 Backups and archives where retrieval can wait Very rare Minutes to hours Objects must be restored before normal access
S3 Glacier Deep Archive
Deep archive		 Long-term retention, compliance archives, rarely retrieved backups Exceptional access Hours Lowest-cost archive profile with the slowest retrieval
S3 Express One Zone
High performance		 Latency-sensitive workloads and frequently accessed data in a single AZ Very frequent, high request rate Consistent single-digit millisecond access Uses directory buckets and a single Availability Zone

Simple selection guide

Use Standard when…

Data is active, frequently accessed, or you want a straightforward general-purpose choice.

Use Intelligent-Tiering when…

Access patterns are unknown or change over time and automatic tiering is valuable.

Use Glacier classes when…

Data is retained mainly for backup, audit, compliance, or long-term archive.

Do not compare only the storage price per GB. Include request charges, data retrieval, minimum storage durations, monitoring charges, replication, and data transfer.

05 — Security

Security and access control

S3 security combines identity permissions, resource policies, public-access controls, encryption, network controls, and monitoring.

Identity-based policies

Attached to IAM users, groups, and roles. They define what that identity may do and on which resources.

Bucket policies

Resource-based JSON policies attached to a bucket. They are useful for cross-account access, service access, and public-read website rules.

S3 Block Public Access

A protective control at account, bucket, or access-point level that helps prevent accidental public exposure.

Access points

Named endpoints with dedicated policies that simplify access patterns for different applications, teams, or networks.

Presigned URLs

Time-limited URLs that grant temporary access to a specific object operation without making the bucket public.

ACLs

A legacy access-control mechanism. For most modern use cases, prefer IAM and bucket policies with Object Ownership controls.

Example least-privilege IAM policy

This example permits listing one bucket and reading objects only under the public-reports/ prefix.

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ListOnlyReportsPrefix",
      "Effect": "Allow",
      "Action": "s3:ListBucket",
      "Resource": "arn:aws:s3:::YOUR-BUCKET-NAME",
      "Condition": {
        "StringLike": {
          "s3:prefix": ["public-reports/*"]
        }
      }
    },
    {
      "Sid": "ReadOnlyReportObjects",
      "Effect": "Allow",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::YOUR-BUCKET-NAME/public-reports/*"
    }
  ]
}

Permission evaluation checklist

  • Is the requester authenticated with the expected identity or role?
  • Does an identity policy allow the requested action?
  • Does the bucket policy allow or deny the request?
  • Is there an explicit deny from an SCP, permissions boundary, VPC endpoint policy, or resource policy?
  • Is Block Public Access preventing a public policy or ACL?
  • Does the KMS key policy allow decryption when SSE-KMS is used?
Explicit deny wins. An explicit deny in an applicable policy overrides an allow. Access troubleshooting must examine all policy layers, not only the bucket policy.

06 — Resilience

Data protection features

Encryption at rest

SSE-S3

S3-managed encryption keys. It is the default encryption configuration for new objects in S3 buckets.

SSE-KMS

Uses AWS KMS keys for greater control, auditability, and separation of permissions. KMS permissions and request costs must be considered.

Client-side encryption

The application encrypts data before uploading it. The application is responsible for key handling and decryption.

Versioning

S3 Versioning retains multiple variants of an object in the same bucket. It helps recover from accidental overwrites, deletions, application mistakes, and some destructive events.

Original: report.csv→ Version A+ Version B+ Delete marker

Deleting an object in a versioned bucket usually creates a delete marker rather than permanently removing every version. Old versions continue to incur storage charges until they are explicitly removed or expired by lifecycle rules.

S3 Object Lock

Object Lock supports write-once-read-many protection. It can prevent object versions from being deleted or overwritten for a retention period or under legal hold. Use it for compliance, immutable backups, and ransomware-resilient designs.

Governance mode

Protects versions while allowing specially authorised users to bypass retention.

Compliance mode

Provides stricter retention that cannot be bypassed by ordinary users, including the root user, during the retention period.

Recommended protection pattern: enable versioning, configure lifecycle rules for old versions, use separate backup copies or replication where needed, and monitor destructive API activity.

07 — Automation

Lifecycle, replication, and operations

S3 Lifecycle rules

Lifecycle rules automate transitions and expiration based on object age, prefix, tags, object size, or version status.

S3 Standard→ 30 days Standard-IA→ 90 days Glacier Flexible Retrieval→ 365 days Expire 
{
  "Rules": [
    {
      "ID": "ArchiveAndExpireLogs",
      "Status": "Enabled",
      "Filter": { "Prefix": "logs/" },
      "Transitions": [
        { "Days": 30, "StorageClass": "STANDARD_IA" },
        { "Days": 90, "StorageClass": "GLACIER" }
      ],
      "Expiration": { "Days": 365 }
    }
  ]
}

Replication

Same-Region Replication (SRR)

Replicates objects to another bucket in the same Region. Useful for separate accounts, data ownership, compliance, and log aggregation.

Cross-Region Replication (CRR)

Replicates objects to a bucket in another Region. Useful for geographic separation, compliance, and latency-oriented copies.

Replication generally requires versioning on source and destination buckets and an IAM role that permits S3 to replicate data.

Operational features

S3 Inventory

Scheduled reports listing objects and metadata for audit, compliance, and large-scale analysis.

S3 Batch Operations

Perform actions such as copy, tag, restore, or invoke Lambda across large object lists.

Event notifications

Trigger SNS, SQS, Lambda, or EventBridge workflows when supported object events occur.

S3 Storage Lens

Organisation-wide visibility into storage usage, activity, cost-efficiency, and data-protection indicators.

CloudTrail data events

Record object-level API activity such as GetObject and PutObject when configured.

CloudWatch metrics

Observe request, error, latency, and storage metrics, depending on the metric configuration.

08 — Performance

Performance and data transfer

Use multipart upload

Upload large objects in parallel parts so failed parts can be retried independently. AWS recommends considering multipart upload for objects around 100 MB or larger.

Use parallel requests

Parallelise independent uploads and downloads to better use available bandwidth and improve aggregate throughput.

Place compute near data

Choose the same Region for S3 and compute when possible to reduce latency and avoid unnecessary inter-Region transfer.

Use CloudFront for delivery

Cache public or authorised content at edge locations to reduce repeated origin requests and improve global performance.

Use Transfer Acceleration selectively

It may improve long-distance transfers through the AWS edge network, but test whether the performance benefit justifies the added cost.

Set caching headers

For web assets, set appropriate Cache-Control and Content-Type metadata.

Useful upload example

# Synchronise a local website directory to S3.
# --delete removes remote files that no longer exist locally.
aws s3 sync ./site s3://YOUR-BUCKET-NAME/ \
  --delete \
  --exclude ".git/*" \
  --exclude "*.map"
Use --delete carefully. It removes destination objects that are not present in the source. Test commands against a non-production bucket first.

09 — Tutorial

Host a static website on Amazon S3

S3 can serve static HTML, CSS, JavaScript, images, and other client-side files. It cannot directly execute server-side code such as PHP, Java servlets, Node.js servers, or database logic.

Security warning: Direct S3 website hosting normally requires public read access to the website objects. AWS recommends keeping buckets private where possible. For a production HTTPS website, use a private bucket behind CloudFront with Origin Access Control.

Option A: direct S3 website endpoint

Best for learning, simple demos, and cases where an HTTP-only public website endpoint is acceptable.

Create a bucket

Choose a globally unique bucket name and an appropriate AWS Region. Avoid placing confidential information in the bucket name.

Upload website files

Upload index.html, an optional error page such as error.html, CSS, JavaScript, images, and other assets.

Enable static website hosting

Open the bucket’s Properties tab, edit Static website hosting, select “Host a static website,” and specify index and error documents.

Review Block Public Access

For the direct public website pattern, adjust the bucket-level public-access settings only after understanding the exposure risk.

Add a public-read bucket policy

Grant s3:GetObject only for objects in the website bucket. Do not grant public write access.

Open the website endpoint

Copy the bucket website endpoint from the Properties page and test the site and error page.

Public-read website policy template

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "PublicReadForWebsite",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::YOUR-BUCKET-NAME/*"
    }
  ]
}
Replace the placeholder. Change YOUR-BUCKET-NAME to the exact bucket name. This policy makes every object under the bucket publicly readable.

Option B: recommended production pattern

🌍 Users Browser requests over HTTPS
→
⚡ Amazon CloudFront TLS, caching, custom domain, WAF
→
🔒 Private S3 origin Access granted only to CloudFront OAC
  • Keep S3 Block Public Access enabled.
  • Create a CloudFront distribution with the S3 bucket as the origin.
  • Use Origin Access Control so CloudFront can read from the private bucket.
  • Configure a default root object such as index.html.
  • Add an ACM certificate and custom domain when required.
  • Configure cache behaviour, compression, security headers, and optional AWS WAF rules.

Minimal website file

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>My S3 Website</title>
</head>
<body>
  <h1>Hello from Amazon S3!</h1>
  <p>This page is served as a static website.</p>
</body>
</html>

10 — Command line

Useful AWS CLI commands

Install AWS CLI v2, configure credentials securely, and ensure the active role has only the permissions required.

Bucket and object commands

# Show all buckets
aws s3 ls

# Create a bucket (example for ap-southeast-2)
aws s3api create-bucket \
  --bucket YOUR-UNIQUE-BUCKET-NAME \
  --region ap-southeast-2 \
  --create-bucket-configuration LocationConstraint=ap-southeast-2

# Upload one file
aws s3 cp index.html s3://YOUR-BUCKET-NAME/

# Upload a directory recursively
aws s3 cp ./site s3://YOUR-BUCKET-NAME/ --recursive

# Synchronise a directory
aws s3 sync ./site s3://YOUR-BUCKET-NAME/

# List objects
aws s3 ls s3://YOUR-BUCKET-NAME/ --recursive

# Download an object
aws s3 cp s3://YOUR-BUCKET-NAME/reports/report.pdf ./report.pdf

# Delete an object
aws s3 rm s3://YOUR-BUCKET-NAME/old-file.txt

# Empty a bucket
aws s3 rm s3://YOUR-BUCKET-NAME/ --recursive

# Delete an empty bucket
aws s3 rb s3://YOUR-BUCKET-NAME

Enable versioning

aws s3api put-bucket-versioning \
  --bucket YOUR-BUCKET-NAME \
  --versioning-configuration Status=Enabled

Configure default SSE-S3 encryption

aws s3api put-bucket-encryption \
  --bucket YOUR-BUCKET-NAME \
  --server-side-encryption-configuration '{
    "Rules": [
      {
        "ApplyServerSideEncryptionByDefault": {
          "SSEAlgorithm": "AES256"
        }
      }
    ]
  }'

Enable static website configuration

aws s3 website s3://YOUR-BUCKET-NAME/ \
  --index-document index.html \
  --error-document error.html

Set content metadata while uploading

aws s3 cp app.js s3://YOUR-BUCKET-NAME/assets/app.js \
  --content-type "text/javascript" \
  --cache-control "public,max-age=31536000,immutable"
High-level vs low-level commands: aws s3 provides convenient file-style commands such as cp and sync. aws s3api maps more closely to S3 API operations and exposes detailed configuration options.

11 — FinOps

Cost model and optimisation

S3 pricing depends on several dimensions. Avoid hard-coding prices into architecture documents because rates vary by Region and can change.

Storage

Amount stored, storage class, object size, minimum billable size, and minimum storage duration.

Requests

PUT, COPY, POST, LIST, GET, SELECT, lifecycle transitions, and other API operations.

Retrieval

Data-retrieval charges for infrequent-access and archival classes.

Data transfer

Internet egress, inter-Region transfer, acceleration, and some cross-service paths.

Management

Inventory, Storage Lens advanced metrics, analytics, replication, Object Lambda, and monitoring features.

Encryption

SSE-KMS can generate KMS request costs. S3 Bucket Keys may reduce KMS request volume for supported workloads.

Cost-optimisation checklist

  • Use lifecycle rules to transition or expire data based on business retention requirements.
  • Use Intelligent-Tiering for unpredictable access patterns after checking object size and monitoring-cost implications.
  • Delete incomplete multipart uploads with a lifecycle rule.
  • Expire obsolete noncurrent versions when retention permits.
  • Compress text-based data and choose efficient file formats for analytics.
  • Use CloudFront caching to reduce repeated origin retrieval and improve delivery.
  • Review small-object economics before moving millions of tiny files into archival classes.
  • Use tags and cost-allocation reporting to identify owners and workloads.

12 — Checklist

Recommended S3 best practices

Security

  • Keep Block Public Access enabled unless public access is an explicit requirement.
  • Prefer IAM roles and short-lived credentials instead of long-lived access keys.
  • Apply least privilege and review explicit denies.
  • Use bucket policies and access points for clear resource boundaries.
  • Use presigned URLs for controlled temporary access.

Protection

  • Enable versioning for important buckets.
  • Use Object Lock where immutable retention is required.
  • Test recovery, not only backup creation.
  • Use replication or independent backup copies where the risk model requires them.
  • Document retention and deletion responsibilities.

Operations

  • Enable appropriate CloudTrail events, logs, alarms, and Storage Lens metrics.
  • Use lifecycle rules for incomplete multipart uploads and stale versions.
  • Use tags for ownership, environment, confidentiality, and cost centre.
  • Automate infrastructure with CloudFormation, CDK, Terraform, or equivalent tooling.

Website delivery

  • Use CloudFront for HTTPS, caching, custom domains, and private-origin access.
  • Use immutable file names for versioned assets.
  • Set correct Content-Type and Cache-Control metadata.
  • Do not store secrets in HTML, JavaScript, or public S3 objects.
Strong default architecture: private S3 bucket + default encryption + versioning + lifecycle rules + least-privilege IAM + CloudTrail monitoring + CloudFront for public delivery.

13 — Troubleshooting

Common problems and fixes

403 AccessDenied when opening an object
Check IAM permissions, bucket policy, Block Public Access, object ownership, explicit denies, VPC endpoint policies, and KMS key permissions. For direct public website hosting, confirm the policy grants s3:GetObject to the exact object ARN pattern.
The website endpoint shows 404 or the wrong page
Confirm the index document name exactly matches the uploaded object key, including case. S3 object keys are case-sensitive. Check whether the file is stored at the bucket root or under a prefix.
CSS or JavaScript downloads instead of loading correctly
Check the object’s Content-Type metadata. Upload CSS as text/css and JavaScript using an appropriate JavaScript MIME type.
Browser requests fail because of CORS
Configure a bucket CORS policy that permits only the required origins, methods, and headers. CORS does not grant S3 permission; the underlying request still requires authorisation or public access.
The AWS CLI reports a region or redirect error
Confirm the bucket Region and the CLI profile’s configured Region. Use aws s3api get-bucket-location --bucket BUCKET when you have permission.
CloudFront returns AccessDenied for a private bucket
Check the Origin Access Control configuration, distribution origin type, generated bucket policy, object key, default root object, and KMS permissions if SSE-KMS is used.
Costs are higher than expected
Examine storage-class retrieval, request volume, noncurrent versions, incomplete multipart uploads, replication, data transfer, KMS requests, and many small objects.

14 — Review

Frequently asked questions

Is S3 a database?
No. S3 is object storage. It is often used as the storage layer for data lakes and applications, but it does not provide the same transactional query model as a relational database.
What is the difference between S3, EBS, and EFS?
S3 is object storage accessed through APIs. EBS is block storage commonly attached to EC2 instances. EFS is a managed shared file system using file-system semantics.
Can S3 host a dynamic website?
S3 hosts static files only. Dynamic features can be built using services such as API Gateway, Lambda, Cognito, DynamoDB, containers, or application servers, while S3 stores the front-end files.
Are S3 objects automatically encrypted?
Yes. New objects are automatically encrypted at rest using SSE-S3 by default unless another supported encryption configuration is selected.
Does S3 versioning replace backups?
No. Versioning improves recovery from overwrites and deletions, but a complete resilience strategy may also require Object Lock, replication, separate accounts, independent backups, monitoring, and tested recovery procedures.
Should a website bucket be public?
For a direct S3 website endpoint, website objects need public read access. For production, a safer pattern is a private S3 bucket behind CloudFront with Origin Access Control.
What happens when I upload an object with the same key?
Without versioning, the new object replaces the previous object at that key. With versioning enabled, S3 stores the new object as another version.
